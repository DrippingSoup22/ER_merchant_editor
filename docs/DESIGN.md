# Design

How ER Merchant Editor is built and the rules it keeps. The save format itself
(the container on both platforms, the regulation's encryption and compression,
BND4, PARAM, character slots and event flags) is
[ER_shared](https://github.com/DrippingSoup22/ER_shared)'s; this project owns
the merchant edits on top of it.

## Packages

Dependencies point inward: the GUI may use the core, the core never imports
Gio, native dialogs or packaging code.

```text
cmd/ermerchanteditor -> internal/ui/gio -> internal/application -> internal/catalog, internal/character, internal/savefile
cmd/shopwrite, cmd/charunlock (diagnostic CLIs) -> the same core
```

| package | owns |
|---|---|
| `internal/savefile` | shop and `EquipParam*` row edits through the embedded schemas |
| `internal/catalog` | items, merchants, shop rows, enrichment, reinforcement, the vanilla baseline |
| `internal/character` | the release gates and bell bearings, per character |
| `internal/application` | one editing session: staged edits and the save plan; no widgets |
| `internal/ui/gio` | layout, widget state, interaction; it never writes a save |
| `internal/platform` | replaceable OS services: file dialogs, paths |
| `internal/assets` | embedded data and item icons |

## Saving

Edits are staged on top of the loaded save and written together by
`application.SavePlan`, a snapshot taken before the Save As dialog opens, so a
change made while the dialog is open cannot slip into the write. The plan runs
its stages through temporary files: character flags, then each `EquipParam*`
table's `sellValue`, then shop rows. A successful save reloads the output and
clears the pending edits; a failure keeps both.

Every stage validates all its edits before writing anything, rebuilds the save,
writes it beside the output, reopens it and checks it, and only then gives it
the output's name. The output may replace a file the user chose in the dialog,
never the input. The rebuild recompresses the whole regulation, so one save can
change any number of rows.

## The game's rules the editor keeps

- **Rows are fixed.** A merchant's range of `ShopLineupParam` rows is chosen by
  its talk script, outside the save: the editor changes what a row sells, never
  how many rows a merchant has.
- **Stock** is `-1` (unlimited) or `1..255`: the game's counter is 8 bits.
- **Price** is capped at `999999`; seven digits corrupted the shop display.
- **A row shows only when its price reaches the item's own
  `EquipParam*.sellValue`**, so a cheap swap also stages a lower `sellValue`.
- **Item swaps keep** the release and stock flags and the currency, clear the
  row's name and icon overrides, and check the target category.
- **Material-priced rows** (`mtrlId != -1`) are shown for context, never edited.
- **Weapon levels** are clamped to the weapon's real maximum: +25 standard,
  +10 somber.
- **Enia's release flags are never written.** They overlap the boss-defeat flags
  `9100-9199`, and changing them triggered boss cutscenes and teleports on real
  hardware. She is left out of the Characters view, her gate action is disabled,
  and staging checks her name again.

## Character flags

A row's `eventFlag_forRelease` is a bit in each character's slot, not in the
regulation. Rows sharing one flag show as one checkbox. Twin Maiden Husks also
lists her bell bearings (`internal/character/bell_bearings.go`): the ones whose
goods are already rows of her own block are hidden there, and the ones that open
another merchant's range through her get their own checkboxes.

A flag write is made on a copy of the bitfield, then checked: only the named
bytes changed and every flag reads back. A PC slot's digest is refreshed after.
A flag whose block is not in the game's table is skipped on reads and refused on
writes. Returning a staged flag to its saved value removes the edit.

## Who sells a row

Paramdex's row names are not a merchant model, so merchants come from
`internal/assets/data/merchant_catalog.json`, generated by
`tools/merchant_catalog/generate.py`. Each row is a `merchant`,
`special_exchange`, `unknown_merchant`, `excluded` or `unnamed`; only real
merchants, unknown real stock and the three Dragon Communion altars are
browsable. Quest-tier suffixes collapse into one NPC; location suffixes stay
where they tell wandering merchants apart. Corrections are generator rules with
their evidence in comments, never runtime exceptions:

- `101898-101899` are Enia's, not Twin Maiden Husks';
- `100250-100252` are Sorcerer Thops', not Seluvis's;
- Raya Lucaria's generic block is the Isolated Merchant's;
- the 1.17 Alteration and Reversion rows are garment services, not stock.

## Data

`internal/assets/data/embed.go` lists the embedded datasets: the item catalog
(`items.json`, with `hidden` and `risky` flags; risky items are hidden by
default), item details, sort order, reinforcement limits and rates, the row
schemas, the merchant catalog and the vanilla shop baseline behind Reset to
Vanilla. The generators in `tools/` rebuild them from Paramdex, SaveForge's item
database and a save whose regulation matches the game; they are not runtime
dependencies. After a game patch, regenerate the baseline and the catalogs.

Two rules for anyone touching them:

- Adjacent PARAMDEF bitfields that share a storage byte stay one group, even
  when one is `dummy8`; otherwise every later offset is wrong.
  `tools/paramdex_schema.py` owns this.
- Four vendored icons (Scorpion Liver, Piquebone Arrow (Fletched), Serpent Crest
  Shield, Golden Lion Shield) are replaced with verified art, downscaled to
  256x256, and pinned by `internal/assets/icons/embed_test.go`.

## The GUI

Three views: **Characters** (the first), **Shop Editor** and **Settings**. Gio
widget state belongs to the frame goroutine; loading, decoding, saving and
native dialogs run outside it and hand back immutable results. Every dimmed
overlay cancels on a press outside its bright panel and ignores presses inside.

Layout rules the tests guard: `panelSurface` for bounded flex regions,
`barSurface` for naturally sized bars; flex spacers return their minimum
dimensions; a divider in an unbounded bar needs a height clamp; the Twin Maiden
Husks sections share one scrolling list; drag payloads are IDs, and a
multi-item drop previews exactly the rows it will fill. New layouts still need a
look in a real window.

## Building and releases

```sh
scripts/check.sh              # vet and test
scripts/build.sh              # the release archive for this host
go run ./cmd/ermerchanteditor # the GUI
```

Windows cross-compiles without cgo; its resources are committed as
`cmd/ermerchanteditor/rsrc_windows_amd64.syso`, regenerated from
`packaging/windows/` with
`go tool go-winres make --in packaging/windows/winres/winres.json --out cmd/ermerchanteditor/rsrc --arch amd64`.
Linux builds natively on Ubuntu 22.04 (for an old glibc baseline) and needs gcc,
pkg-config and the Wayland, X11, xkbcommon, EGL/GLES, libffi, Xcursor, Xfixes and
Vulkan development packages; its file dialogs need `zenity`, `matedialog` or
`qarma` at run time. Under WSL the GUI scales by 1.25; `ER_EDITOR_UI_SCALE`
(0.5 to 3) overrides it. macOS packaging is kept for later and not built.

`.github/workflows/release.yml` tests and vets on both targets, packs each
archive with ER_shared's `releasezip`, and attaches them to a draft release.

## Tests

The tests that need a real save read `save_files/` (git-ignored, read-only) and
skip without it: `vanilla_fresh_character.dat` (PS4, eight characters) and
`pc_fixture.sl2` (PC). They write only to temporary directories.
