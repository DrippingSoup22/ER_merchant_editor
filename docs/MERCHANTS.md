# Merchant identity

`data/shop_row_names.json` (raw Paramdex Names file, 1261 entries) mixes
three different things under similar `"Name - Suffix"` strings, so it's not
a usable merchant list as-is. `data/merchant_catalog.json` (generated by
`tools/merchant_catalog/generate.py`, reads only local repo data, no
network) is the reconciled row_id -> `{merchant, kind}` mapping the app
should use instead. Keep the raw Names file for debugging/cross-checking;
never hand-edit the generated catalog — change the rules in `generate.py`
and re-run.

`kind` values: `merchant` (real NPC, editable), `special_exchange` (real
trade, no owning NPC — Alteration/Reversion/the 3 Dragon Communion altars),
`unknown_merchant` (real purchasable rows we can't confidently attribute to
one NPC), `excluded` (debug/unreachable, not really in the game), `unnamed`
(no Names-file entry at all, pre-existing gap).

Sources: [Fextralife Merchants](https://eldenring.wiki.fextralife.com/Merchants)
for the roster; individual item pages cited inline below.

## Same NPC, multiple unlock tiers (merged to bare name)

Brother Corhyn, Miriel, Sorceress Sellen, Preceptor Seluvis, Twin Maiden
Husks — Paramdex splits each into `"Name - <prayerbook/scroll/quest>"` per
unlock tier; same person, collapsed to the prefix.

**Enia** splits three ways: `"Enia - <Boss>"` (armor, sold outright),
`"Enia - Forging"` (hand-in rows for the remembrance itself, 101775-101792),
`"Remembrance of <Boss>"`/`"Elden Remembrance"` (the actual reward rows,
101900-101948). All merge to `Enia` (116 rows) — she's the Roundtable Hold
"Palm Reader" who exchanges Remembrances for rewards.

## Look similar, are real distinct NPCs (not merged)

Paramdex's generic `"Merchant - <Location>"` labels are normalized to the
actual stock owner in the UI: the Nomadic merchants, the Hermit merchants at
Ainsel River and Mountaintops, and the Abandoned Merchant at Siofra River.
`"Hermit/Imprisoned/Isolated Merchant - <Location>"` are likewise separate
wandering-merchant NPCs — the suffix is identity here, not an unlock state.

## Non-NPC mechanic pseudo-shops (`special_exchange`, 371 rows)

- **Alteration** (166 rows) / **Reversion** (166 rows): armor-recolor
  trade, `price=0`, every row an `mtrlId` swap. No owning NPC, not exposed
  in the editor (a recolor pair isn't really "browsing a shop").
- **Dragon Communion** (19 rows total, corrected from an initial 39 — see
  below): a Dragon Heart-for-incantation altar mechanic, but **3
  physically distinct altars, exposed as 3 separate merchants** (split
  2026-07-31 — originally merged into one "Dragon Communion" bucket, but
  in-game testing showed the Grand Altar sells only its own 3 items, none
  of the base game's, which the merged view contradicted).
  [Fextralife](https://eldenring.wiki.fextralife.com/Dragon+Communion)-
  confirmed 3 real altars, matched item-for-item with zero overlap between
  them: **Church of Dragon Communion** (Limgrave, 3 items, row
  101975/101976/101980), **Cathedral of Dragon Communion** (Caelid, 13
  items: the Church's own 3 + Dragonice/Glintstone Breath/Rotten Breath
  always-available + 7 dragon-kill-gated, row 101950-101962), **Grand
  Altar of Dragon Communion** (DLC, 3 items: Ghostflame Breath
  always-available + Bayle's Tyranny/Flame Lightning, row
  102350/102351/102355). Exposed in the editor
  (`browsableSpecialExchanges` in `app/catalog/catalog.go`) as 3 separate
  browsable, Dragon-Heart-priced (`costType` 1 or 5, not runes — see
  `docs/SHOP_LINEUP.md`) item lists; kept as one contiguous block in
  `MerchantSortKey`'s ordering (`dragonCommunionAltarRank`, real-altar
  order not alphabetical) rather than scattered by name.
  - The Church's 3 items and 3 of the Cathedral's 13 are the *same*
    incantations (Dragonfire/Dragonclaw/Dragonmaw), each pair sharing an
    identical `eventFlag_forStock` — deliberate FromSoft design (buying at
    either altar marks both as purchased), not a data bug. Only visible as
    an apparent "duplicate" when both altars are merged into one flat
    list, which real gameplay never does (you're only ever at one altar).
  - Bayle's Tyranny/Flame Lightning show no gating in our data (`mtrlId=-1`,
    `unlockFlag=0`) despite needing the DLC's "Heart of Bayle" in real
    play — not a bug, that requirement isn't encoded in `ShopLineupParam`
    at all, must be enforced by the NPC's talk-script checking inventory
    directly. General caveat: no gate encoded here means "no gate in this
    table," not "provably available from the start."
  - **Correction**: 20 rows (four identical 5-incantation blocks, row
    900000/900010/900020/900030, symbolic 1-5 rune prices) were initially
    merged in as "4 more altars" on pattern-matching alone. Reclassified
    `excluded`: all 4 blocks share one literal `eventFlag_forStock` (not 4
    independently-tracked altars), the real 3-altar roster above already
    accounts for every live row, and 2 of the 5 items show unconditionally
    available here despite being confirmed dragon-kill-gated at the real
    Cathedral. Stale/superseded rows from an earlier shop-table revision.
    Dragon Communion dropped from 39 to the correct 19 rows.

## Real, unattributed rows (`unknown_merchant`, 9 rows, ex-"Sorcery")

Rows 102300-102308. Prices match **Count Ymir** (DLC, Cathedral of Manus
Metyr — absent from Paramdex's Names file entirely, likely just a coverage
gap) for 4 items, and Sellen/Seluvis prices for the other 5 — but not
certain enough to guess-merge, so left as a distinct honestly-unlabeled
bucket: real and editable, just unattributed.

## Excluded, not reachable in real play (24 rows, ex-"Incantation"/"Sorcery")

Row 1600404/1600405/1600407/1600408 (Glintstone Pebble dupe, Stars of Ruin,
Flame Fall Upon Them, Frenzied Burst) — each confirmed a corpse
pickup/mini-boss reward/scarab drop elsewhere in the real game, no NPC's
talk-script ever opens these rows. Plus the 20 stale Dragon Communion
duplicate rows above.

## Row-level misattributions

Full audit (6 parallel agents, one per merchant group, Fextralife
cross-check) across all 34 merchants / 616 rows found 2 real bugs, both
FromSoft reusing a free row-table slot near an existing NPC's block for
DLC/other-NPC content, with Paramdex's Names file labeling the slot after
its neighbor instead of its true owner. Fixed via `ROW_REASSIGNMENTS` in
`generate.py`:

- **101898/101899** ("Enraged Divine Beast" talisman + "Divine Beast Frost
  Stomp" AoW), labeled Twin Maiden Husks, are actually **Enia**'s reward
  pair for "Remembrance of the Dancing Lion" (same `price=0`+`mtrlId`
  signature as every other Enia reward row).
- **100250/100251/100252** (Glintstone Pebble/Arc/Starlight), labeled
  Preceptor Seluvis, are **Sorcerer Thops**'s shop (Church of Irith) — a new
  35th canonical merchant (absent from Paramdex entirely; prices match
  Thops's known trio exactly, and Fextralife states Starlight specifically
  is not sold by Seluvis).

**Also one archetype mislabel:** the block Paramdex calls `"Merchant -
Academy of Raya Lucaria"` (implying a Nomadic Merchant) is actually the
**Isolated Merchant** at Raya Lucaria (17-row stock matches Fextralife's
Isolated Merchant page exactly) — renamed via `MERCHANT_RENAMES`. The same
normalization names the generic Ainsel River/Mountaintops blocks as **Hermit
Merchant** and the Siofra River block as **Abandoned Merchant**.

**Audited clean:** the generated catalog currently contains 38 canonical
merchant names across 640 attributed rows, including 10 Nomadic merchants,
3 Hermit merchants, 3 Isolated merchants, the Imprisoned Merchant, and the
Abandoned Merchant. The archetype prefix is intentionally part of each
generic merchant's displayed identity.

**4 more TMH items double-checked, all legitimate** (Flask of Wondrous
Physick base/Whetstone Knife/Crafting Kit/Talisman Pouch, rows
101878-101881): real catch-up items TMH sells past a certain progression
point — not a misattribution, just an unlock-gated fallback not currently
surfaced as such.

Separately (not attribution issues): two Liurnia rows (100636/100637) where
`item_name`/`label` disagree by one smithing-stone tier — cosmetic only.

## DLC (SotE) merchants (`DLC_MERCHANT_ROW_RANGES`)

Paramdex's Names file gives DLC rows no `[Merchant]` prefix (base-game
rows have one; DLC rows are bare item names or generic `[Sorcery]` —
checked against upstream master, no update to pull), so these are
attributed by row-id range in `generate.py`:

- `102250-102266` — **Moore** (17 rows; wiki inventory matches
  item-for-item, incl. Note: Sealed Spiritsprings).
- `102270-102282` — **Thiollier** (13 rows; self-identifying —
  Thiollier's Concoction).
- `102300-102308` — **Count Ymir** (9 rows; wiki matches incl. both
  bell-quest tiers; these were the ex-`unknown_merchant` "Sorcery" rows,
  that bucket is now empty).

The Grand Altar of Dragon Communion (102350/102351/102355, Bayle tier)
was **already** mapped as its own row set
(`DRAGON_COMMUNION_GRAND_ALTAR_ROW_IDS`, see the Dragon Communion section
above) — no separate DLC-merchant handling needed here.

## Regenerate

```
cd tools/merchant_catalog && python3 generate.py
```

Reads `data/shop_row_names.json` only (no network). Re-run after any rule
change above, or after re-running `tools/paramdex_extract` if Paramdex's
Names file changes upstream.
